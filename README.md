# Fumi

**Password-protected messaging. Calling disabled by design.**

Fumi is an independent, unofficial Signal Desktop fork for Apple Silicon Macs. It adds cryptographic password protection at startup and disables calling for people who want to use Signal for messaging only.

Its design focuses on protecting access to the local message database and reducing the processing, device access, and diagnostic data associated with features outside that messaging-only purpose. Fumi uses the Signal service and is not affiliated with Signal.

## Cryptographic password protection — not just a screen lock

Your password protects the key that opens the message database, not merely access to the interface.

Fumi retains Signal Desktop’s SQLCipher database encryption and macOS Keychain-backed key protection. A key derived from your password using scrypt adds an AES-256-GCM encryption layer around the already macOS-protected database key.

Password setup or unlock must complete successfully before the message database is initialized and opened.

### Lock ends the application session

Lock closes the message database and quits Fumi, ending the application process. The next launch requires your password before the database opens.

Closing the main window follows the same shutdown flow. This makes ending the session and requiring a password on the next launch part of ordinary application use.

## Calling disabled — not just hidden or muted

Fumi disables incoming and outgoing direct calls, group calls, and call-link calls at the processing level.

Incoming call signaling is blocked before it reaches the calling engine. Calling-service initialization, outgoing call preparation, and call-connection setup are disabled. Background call-state queries and call-link operations are also blocked.

The aim is to reduce calling-related attack surface and avoid the additional network activity and traffic patterns generated by call setup and real-time media sessions.

Existing call-history entries remain available alongside your messages.

## Microphone and camera capture disabled

Microphone and camera capture are fixed disabled. Application requests for audio or video capture are denied regardless of saved permission settings.

New voice-message recording is also disabled, with the recording path stopped before an operating-system permission prompt or microphone capture begins.

Existing audio and video playback, received voice messages, and file attachments remain available.

## Diagnostic logging disabled

Application diagnostic logging is disabled at the shared logger, including early startup logging. Diagnostic-report collection, log upload, and crash-report generation are also disabled.

At startup, Fumi removes its own `logs` directory while retaining configuration, message databases, attachments, and other profile data.

## Application isolation

### Independent profile and Keychain context

Fumi has its own application identity, macOS Keychain protection context, and data directory:

```text
~/Library/Application Support/Fumi
```

A first installation starts with a new Fumi profile and device setup. Official Signal’s profile remains separate and untouched.

Subsequent Fumi updates preserve the existing Fumi profile, message database, and password-lock data.

### Isolated CAPTCHA verification

When Signal requires CAPTCHA verification, Fumi opens the challenge in a dedicated sandboxed window with a separate, non-persistent browser session.

The verification page runs with Node integration disabled, permissions denied, and no application bridge. Completion is passed back to Signal’s existing verification flow.

Start with these files to examine Fumi’s core security and privacy changes:

- [Startup, database access, and shutdown](https://github.com/fumi-soft/fumi/blob/main/app/main.main.ts) — password setup and unlock before database initialization, database-key retrieval, and the Lock/quit lifecycle.
- [Calling-service barriers](https://github.com/fumi-soft/fumi/blob/main/ts/services/calling.preload.ts) — disabled calling initialization, incoming signaling, call setup, and call-link operations.

## Getting started

### Set your password

Create a password on first launch. Every subsequent launch requires that password before opening the AES-256-encrypted message database.

If you lose your password, you must reset Fumi’s local data on this Mac, including message history and settings, and complete setup again. Password recovery is not implemented. The reset removes Fumi’s local data from this Mac; it does not delete your account on the Signal service.

### Choose your language

Fumi provides English and Japanese interfaces. Preferences offers System Language, English, and Japanese.

Automatic language selection uses Japanese when the resolved system language is Japanese, and English otherwise. Regional date, time, and currency formatting continues to follow your locale settings.

## Download and updates

**System requirements:** macOS 13 (Ventura) or later, on a Mac with Apple silicon (arm64).

Download the macOS Apple Silicon DMG from [Fumi Releases](https://github.com/fumi-soft/fumi/releases).

Source code is available in the [Fumi repository](https://github.com/fumi-soft/fumi); you can build the application using the instructions below.

Fumi updates are manual. Install a newer build by replacing the application bundle while keeping the existing Fumi profile and password-lock data.

The official Signal updater is disabled. Build-expiration checks remain active.

## Build from source

Build on a Mac with Apple Silicon using the exact Node.js and pnpm versions declared in [package.json](package.json), and the Xcode Command Line Tools.

Run the following commands from the source directory:

```sh
pnpm install --frozen-lockfile
pnpm run build:fumi
```

The command generates production assets and builds:

- `release/fumi/fumi-desktop-mac-arm64-<version>.dmg`, containing `Fumi.app` and an `/Applications` link.
- `release/fumi/mac-arm64/Fumi.app`, the retained unpacked application.

After bundle processing, the application is ad-hoc signed and its signature is verified before DMG creation. A signing or verification failure stops the build. The application is not Apple-notarized, and the build command does not publish a release.

A missing or empty `SOURCE_DATE_EPOCH` defaults to build-start Unix time in seconds; a supplied non-empty value is preserved. Build creation and expiration use this timestamp, so source archives do not require Git metadata.

## Who Fumi is for

If you are already satisfied with official Signal Desktop, Fumi is not recommended for you. Every launch requires a password. Calling is disabled. Closing the main window quits the application, and returning to your messages requires entering your password again. If you do not need these restrictions, Fumi simply makes everyday use less convenient.

Fumi is designed for human rights defenders, journalists, and others whose security and privacy requirements make these restrictions necessary. Password-protected access to the local message database, disabled calling and capture, and ending the application session when the window closes are treated as baseline requirements rather than optional preferences.

For these users, the restrictions are the reason to choose Fumi.
